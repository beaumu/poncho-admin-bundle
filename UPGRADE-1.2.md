UPGRADE FROM 1.1 to 1.2
=======================

Security
--------

 * Deprecate `BaseAdminUser::eraseCredentials()`, use `erasePlainPassword()` instead

   `UserManager::updatePassword()` now calls `erasePlainPassword()`. If your admin
   user entity overrides `eraseCredentials()` to clear data of its own, move that
   logic into `erasePlainPassword()` so it keeps running after a password change:

   Before:
   ```php
   class AdminUser extends BaseAdminUser
   {
       public function eraseCredentials(): void
       {
           parent::eraseCredentials();
           $this->totpSecret = null;
       }
   }
   ```

   After:
   ```php
   class AdminUser extends BaseAdminUser
   {
       public function erasePlainPassword(): void
       {
           parent::erasePlainPassword();
           $this->totpSecret = null;
       }
   }
   ```

   Anything that must never reach the session belongs in `__serialize()`
   instead: Symfony 7.3+ no longer calls `eraseCredentials()` after login once
   the method is marked `#[\Deprecated]`, which it now is.

 * `deleteLink()`, `moveUpLink()`, `moveDownLink()` and `moveLinks()` now send a CSRF token

   This closes a real hole: previously these sent a plain, unauthenticated `GET`
   that anyone could trigger with a crafted link. Controllers generated by
   `make:admin:table`/`make:admin:tree` **since this release** check the token
   automatically — nothing to do if your CRUD was generated with 1.2 or later.

   **If your CRUD was generated before 1.2**, its `delete()`/`move()` actions
   don't check the token yet, and now silently ignore the `_token` query
   parameter the link sends. Add the check by hand:

   Before:
   ```php
   #[Route('/delete/{id}', requirements: ['id' => '\d+'])]
   public function delete(int $id): Response
   {
       $entity = $this->findOrNotFound(Mission::class, $id);
       $this->removeAndFlush($entity);

       return $this->js()->reloadTable()->toastSuccess('Item deleted');
   }
   ```

   After:
   ```php
   use Poncho\AdminBundle\Lib\DataTable\ColumnActionBuilder;

   #[Route('/delete/{id}', requirements: ['id' => '\d+'])]
   public function delete(Request $request, int $id): Response
   {
       $intention = ColumnActionBuilder::csrfIntention('mission_delete', ['id' => $id]);
       if (!$this->isCsrfTokenValid($intention, $request->query->getString('_token'))) {
           throw $this->createAccessDeniedException('Invalid CSRF token.');
       }

       $entity = $this->findOrNotFound(Mission::class, $id);
       $this->removeAndFlush($entity);

       return $this->js()->reloadTable()->toastSuccess('Item deleted');
   }
   ```

   Do the same for `move()`, using `'<name_prefix>_move'`. See
   [Security](docs/security.md#csrf-on-delete-move-and-bulk-action-routes) for
   the full explanation, and for protecting any other link you built around
   `ColumnActionBuilder::link()`.

 * The password-reset e-mail now escapes the recipient's name

   If you overrode `@PonchoAdmin/email/password_reset.html.twig`, apply the
   same fix: wrap any `trans()` placeholder that can hold a user-editable value
   with `|e`, keeping the surrounding message `|raw` (it legitimately contains
   the reset link's markup).
